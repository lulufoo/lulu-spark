# Android bindService 的绑定链路、生命周期与死亡通知机制 — 要点摘要

> **导航**：[distilled](../../../distilled/android-dev-docs/framework-principles/3.bindling-lifecycle-and-death-notification-mechanism-distilled.md)

## 要点

1. **onBind() 返回值被 AMS 缓存，后续同 Intent 绑定不会再次调用**
   AMS 缓存第一次 onBind() 返回的 IBinder，同一 Intent 的后续绑定请求直接走缓存。绑定引用计数：bind 加一，unbind 减一，归零才触发 onUnbind()+销毁 Service；若 Service 同时被 startService 启动，引用归零后也不销毁，还需 stopService。

2. **AMS 只注册一个 DeathRecipient：挂在 IApplicationThread 上而非每次 bindService**
   进程 attach 时对 IApplicationThread 注册唯一一个死亡监听，后续每次 bindService 建立 ConnectionRecord 但不额外注册。死亡通知一次批量清理该进程所有 ConnectionRecord（O(1) 监听 + O(n) 遍历清理），这是设计上的关键权衡。

3. **ConnectionRecord 直接持有 ServiceRecord 字段引用，无需反向查找表**
   AMS 收到死亡通知后，通过 ProcessRecord 拿到所有 ConnectionRecord，每个 ConnectionRecord 直接持有对应 ServiceRecord 的引用，批量清理路径不需要额外的反向查找映射。
