# DDM Phase：生成（Compose 模式）

> **⚠️ 本文件是 `dtd_distill_compose` 的执行规范，必须由 `SKILL.md` 显式加载后执行，禁止 AI 自行推断内容。**
>
> **配置参考**：[ddm-concepts.md](ddm-concepts.md)（路径符号定义）
>
> **输入**：`DIAGNOSE`（`diagnose/<topic-path>/<ts>-<slug>.md`）；读取文件全文作为诊断摘要输入。若该文件不存在，须告知用户先执行 Phase 1。`<topic-path>`、`<ts>`、`<slug>` 从对应 raw 路径解析。
>
> **输出**：`DISTILLED`，完整 distilled Markdown 文档，写入 `distilled/<topic-path>/<ts>-<slug>.md`（`<ts>` 与 `<slug>` 从 DIAGNOSE 文件路径解析，不得新造时间前缀）。

> ⚠️ 生成时逐条对照诊断摘要，不依赖记忆。

## PART 1 — 理论与规则

> 双轴归属模型、认知事件完整语境、认知事件层次定义见 [ddm-p1-diagnose.md](ddm-p1-diagnose.md) PART 1，此处不重复。

### 叙事主轴

文档的每个视觉单元（首段、章节标题、段落、代码块、表格、偏差记录）都必须承载路径要素。段落不以知识陈述为组织中心，而以**路径推进**为组织中心。

DDM 不复现原始对话，也不只摘录结论；它保留的是足以重建理解过程的最小必要路径。核心主张：

> 推导路径由认知事件串联而成。每个认知事件包含三部分：**触发条件**（为什么走到这里）、**认知动作**（谁完成了什么推导）、**落点指向**（终结哪个疑问，或打开哪个新疑问）。

---

### 附录为什么存在

有些内容不一定进入正文推导链，但仍有独立价值，例如：

- 对照表
- 框架骨架
- 操作清单
- 边界定义
- 决策准则
- 源码入口标识（函数名、常量名、文件路径等可直接查证的具名标识）

处理原则：**优先塞回正文；无法自然归属时再进入附录。**

## [P2-1] 文档结构

**文档头部**（固定）：

```markdown
# [根据对话内容抽象的精确标题]

> 创建时间：[与 <ts> 一致的中文日期时间，规则见 ddm-concepts.md]

> **导航**：[digest](...) | [raw](...)（由 Phase 4 落盘时注入）

> 本文档基于一次[对话类型]整理。
> 目标是重建理解过程——跟着推导走一遍，而不是直接读结论。

## 本次对话在追什么

对话从「[起点疑问或直觉]」出发，按一条可重走的主线推进：

- [转折点 1：一句话指明发生了什么]
- [转折点 2]
- ...

文末保留[未展开方向或遗留问题]，便于单独补课。
```

> 「本次对话在追什么」只来源于：[P1-7] 主线概要、章节规划、附录候选、遗留问题。它呈现的是路径骨架，不是章节目录。

**章节顺序**：

```text
1. 对话目标与边界（仅当诊断摘要中有内容时输出）
2. 正文章节（按诊断摘要「章节规划」）
3. 事实性偏差（固定）
4. 引导质量问题（仅当诊断摘要中有此项时输出）
5. 遗留问题（固定）
6. 附录（仅当附录候选非空时输出）
```

**章节标题规则**：

```text
· 使用疑问句、悬念句或事件句
  ✅ 「公平：FIFO 队列为什么仍可能『不公平』」
  ✅ 「内部靠什么站得住：持有者、重入深度、CAS 与等待路径」
  ❌ 「ReentrantLock 的公平性机制」
  ❌ 「AQS 内部字段说明」
```

## [P2-2] 正文写法

每章按以下方式生成：

```text
· 开篇先呈现疑问或直觉来源，不直接给答案
· 主体顺序：触发条件 → 初始直觉/猜测 → 保留的认知事件 → 校准后的准确表述 → 路径钩子
  · 路径钩子只在确实引出下一疑问或下一节时添加；否则可止于准确表述
  · 典型句式：「但 X 本身没解释 Y，于是下一个问题就逼出来了：……」

· 段落之间用因果链或方向翻转显式衔接
  · 可用：「顺着 X，自然问到 Y」「但 X 又打开了新问题 Y」
  · 禁用：「另外」「此外」「还有」「同时」等平行过渡词

· 归属表达（对照 [P1-7]）：
  [U/U]         「你主动识别出/质疑……」
  [U/AI] 高自主  「在这个方向上，你独立识别出……」
  [U/AI] 低自主  「顺着这个方向，你归纳出……」
  [A/AI]        「面对你这一步的疑问，需要把 X 摊开：……」
                或「这里必须插一个事实才能继续往下走：……」
  [A/U]         「你这个问题指向了一个需要澄清的细节：……」

· 反直觉结论：确认对应证据已保留
· 闭环落点：确认闭合事件已保留
· 同段混合时：[U] 优先置前，[U/U] 优先于 [U/AI]，[A] 作为补充
· 塞回正文的片段标注 [补]
· 不用「问：」「答：」标签；去除对话噪音；禁止输出 DDM 内部术语
```

## [P2-3] 固定章节模板

**事实性偏差**（固定）：

```markdown
## 对话中出现的事实性偏差（回答者视角）

> 以下记录本次推导中出现的明确事实性偏差。
> 每条保留「触发语境」，避免把路径事件扁平化为知识勘误。

| 触发语境 | 偏差描述 | 校准后的表述 |
|---------|---------|-------------|
```

**引导质量问题**（条件输出）：

```markdown
## 对话中出现的引导质量问题（回答者视角）

> 以下记录本次对话中出现的引导策略失效或方向偏移，供路径复用时参考。

| 问题描述 | 影响范围 | 对话中的处理结果 |
|---------|---------|----------------|
```

**遗留问题**（固定）：有序列表，每条一句话，按优先级排序；若已有显式遗留清单则直接采用。

## [P2-4] 附录机制

```text
Step A：扫描遗漏
        对照诊断摘要中的「附录候选」，
        并补充推导区未覆盖但仍有价值的内容
        典型类型：对照表、框架骨架、操作清单、边界定义、决策准则、
                  源码入口标识（函数名、常量名、文件路径）

Step B：归属判断
        · 能塞回正文且不破坏叙述流 → 塞回，标注 [补]
        · 独立结构或横跨多章节 → 保留在附录

Step C：附录输出
        按内容类型分组，每条标注「来源：[章节名]」
        候选为空则省略附录章节
```

---

## [P2-5] 格式规则

```text
· 输出必须是完整 Markdown 文档
· 落盘路径：`distilled/<topic-path>/<ts>-<slug>.md`（与 raw/digest 同相对路径）；`<slug>` 全小写、连字符；`<ts>` 与 raw 及 `index.json` 的 `common_path` 一致
· 代码块：用于机制链、流程步骤、框架骨架
· 表格：用于对比关系、对照表、偏差记录、诊断结果
· 代码块或表格前必须有一句路径溯源，说明它为什么在这里出现
  ✅ 「顺着『新线程会不会被拦下』的追问，这道闸门大致插在这里（示意）：」
  ❌ 直接贴代码或表格而无溯源引入
· 标题层级：一级=文档标题；二级=章节；三级=子疑问/附录内容类型
```
