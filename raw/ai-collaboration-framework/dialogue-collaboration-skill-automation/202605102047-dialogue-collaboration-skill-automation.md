方案3的问题不是"不该用"，而是：**如果每次都要用户手写完整路径，摩擦太高，习惯就建立不起来**。解决的方向是降低执行成本：

- **Snippet / 快捷触发**：用一个简短关键词（如 `/coding`）展开为完整的加载指令

## 为什么"先查证，再结论"在隐式状态下会失效

这条规则在对话规范里是**背景约束**，但 AI 的执行优先级是：**任务紧迫性 > 背景约束**。

当用户说"这个 bug 是什么原因"，AI 接收到的最强信号是"给出原因"，而不是"先查证"。背景约束在任务压力下被稀释——这和意图漂移的机制完全一样：**上下文中最显著的内容会覆盖早期声明的约束**。

"先查证，再结论"放在系统规则里，等同于**放在自律层**——依赖 AI 每次记得执行。

## SKILL 做了什么

当 BUG 分析被封装成 SKILL，调用时发生的事情：

1. **"先查证，再结论"变成当前任务的前置步骤**，不再是背景约束——它和任务本身在同一层级出现，不会被稀释
2. **每次调用 = 一次完整的意图锚定**：不只是锚定"分析这个 bug"，同时锚定"用什么方式分析"
3. **用户的触发成本极低**：调用一个 SKILL 名，而不是每次手写规则

这正是意图管理文档里"意图显式锚定"的设计意图：**不依赖上下文自动保留，在需要时主动重新注入**。

## SKILL 结构的设计含义

一个 BUG 分析 SKILL 不只是"提示词的快捷方式"，它是一个**任务协议容器**：

```
BUG 分析 SKILL
├── 执行前置约束（先查证，再结论）
├── 分析步骤框架（重现路径 → 追踪 → 归因）
├── 输出格式约定（证据标注：✅已验证 / ⚠️推断）
└── 完成标准（结论必须能对应到具体证据）
```

每次调用，这套框架整体注入——不是用户"记得要求 AI 查证"，而是**查证已经是这个任务类型的结构性组成部分**。

## 和三层保障机制的映射

| 层 | BUG 分析场景的对应 |
|---|---|
| 自律层 | 用户每次记得说"先查证再结论" |
| 规则层 | `coding-global.instructions` 里有这条规范，靠平台/AI 自动执行 |
| **结构层** | **调用 BUG 分析 SKILL，规则随任务结构一起注入** |

SKILL 是把规则从规则层提升到结构层的工程手段。

## 效率的本质：意图锚定成本的分摊

对话式协作里，结构层的意图显式锚定是**每次对话都要支付的固定成本**。对一个新问题，这个成本有价值——探索过程本身在积累理解。

但对 BUG 分析这类高度重复任务：

```
问题结构固定 + 规则固定 + 执行路径固定
→ 每次支付锚定成本 = 纯摩擦，无新增价值
```

SKILL 做的事是：**把这个成本从"每次会话内支付"变成"一次设计，无限次零成本复用"**。这不只是方便，是任务性质决定的效率边界。

## 对话式 → 自动化 的生命周期

这个生命周期可以精确描述：

```
新问题（意图模糊）
  → 探索发散式对话
  → 问题边界清晰 + 规则稳定
  → 识别：这是可重复的结构化任务
  → 沉淀为 SKILL（一次设计，意图规则内嵌）
  → 后续执行：自动化协作，零锚定成本
```

这个路径本身是**协作设计层 → 协作路径设计**的一个子模式，但当前框架里还没有显式定义这个跨模式的生命周期。⚠️ 这是框架目前的一个空缺。
