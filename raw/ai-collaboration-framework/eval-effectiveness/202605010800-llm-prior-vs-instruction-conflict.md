## AI（Turn 2）

问题本质是：**模型读了约束，但用常识推断（"目标文件不存在，链接没意义"）覆盖了显式规则**。这是 spec 设计问题，不是模型能力上限。

有三个可行方向，效果递增：

---

### 方案 A · 负向禁令 → 正向义务 + 场景预判

当前 spec 用的是"禁止占位"（负向），模型在面对"目标文件尚不存在"的场景时，常识优先级高于禁令。

改法：在 Step 2 的导航规则里，显式命名这个场景并给出正确行动：

> **导航链接规则（强制）**：`ts`、`slug`、`topic-path` 在 Step 1 完成后即完全确定，所有路径**立即可计算**。目标文件是否已存在与此无关——后续 Phase 才会创建这些文件，这是设计意图。**必须**一次性写入完整路径，不得使用任何占位文字。

核心：让模型看到"文件不存在是预期的，不是写占位的理由"。

---

### 方案 B · 加"路径预计算"子步骤

在正式生成文档之前，强制模型先输出一个计算块：

```
pre-flight（必须先输出，再写文档）：
  N        = ？
  prefix   = ？
  distilled_path = ？
  digest_path    = ？
  trace_path     = ？
```

计算结果显式落到输出后，再进入文档生成。模型填完具体值再继续，没有"留到后面填"的操作空间。

---

### 方案 C · 添加验证门控（最强）

在 Step 2 末尾加一条自检规则：

> **提交前自检**：扫描生成的文档头部，若导航行包含任何中文说明文字、括号注释、或非 URL 文本，则判定为格式违规，必须重写。

将违规特征具体化（中文文字、括号），比"禁止占位"更易被模型识别匹配。

---

**推荐**：A + C 组合，成本最低、覆盖最准。B 适合如果 A+C 仍然复发的情况。

## AI（Turn 3）

当前显式约束有两处，都在 ddm-p0-normalize.md Step 2：

**处 1**（blockquote 注释）：
> `COMMON_PATH` 和 `prefix` 可立即计算，**raw / distilled / digest / trace 的完整路径一次性写入，不得使用占位符**。

**处 2**（bullet 禁令）：
> 禁止：… / 导航行使用"待落盘后更新"占位

---

**为什么没起效：两处约束都只针对"结果"，没有切断"原因"。**

模型产生占位的内部推理链是：

> "distilled / digest / trace 文件尚不存在 → 写链接指向不存在的文件是不正确的 → 改用占位说明更合理"

两处约束都是在禁止这个推理链的**末端输出**（不许写占位），但没有截断推理链的**起点假设**（"目标文件不存在 = 不应写链接"）。

禁令在与常识竞争时，常识赢了——因为 spec 没有告诉模型"目标文件此时不存在，是设计意图，不是写链接的障碍"。

---

**症结一句话**：约束的施力点是输出形式，但问题发生在推理前提。规则没有错，但打的不是同一个位置。

## AI（Turn 4）

**LLM 单次推理的实际过程：**

模型是自回归生成的——逐 token 向右，已生成的 token 不可修改。"生成 → 检查 → 回头改"这个循环，在单次推理内部不存在。

**方案 C 的实际机制是什么：**

自检指令在 prompt 里，模型在生成第一个 token 前已读完。它的作用是**前向影响**——让模型在生成导航行时"预知"后面会有检查，从而更谨慎。

但这个前向影响非常脆弱：当常识推理（"文件不存在不该写链接"）足够强，前向影响往往被覆盖。并且即使自检步骤真的生成了，模型也可能把一个有问题的导航行判定为"通过"——因为自检本身也是自回归生成的，它描述的是当前 token 流，而不是真正回头审查。

**所以方案 C 本质上和现有约束是同一类施力：结果层压力。**

---

**真正有效的介入点只有一个：在推理起点修正前提。**

这对应方案 A——在模型构建"目标文件不存在"这个前提之前，告诉它这个前提本身是错的：

> "后续 Phase 才会创建这些文件，这是设计意图。文件不存在是预期状态，不影响路径计算。"

这不是在约束输出，而是在纠正推理的输入假设。机制上比禁令和自检都更靠前。

## AI（Turn 5）

**问题一：是否普遍？**

有结构性依据，但不是无条件的普遍规律。

当模型内部存在一个**与目标输出竞争的强推理**时，输出层约束处于劣势——因为模型生成是自回归的，它的"自然输出"由内部推理决定，约束只是在与已形成的推理方向对抗。

如果不存在竞争推理（模型本来就会输出正确结果），输出层约束完全够用，也没必要去纠正假设。

所以更准确的表述是：**竞争推理越强，约束越需要前移到推理起点。**

---

**问题二："纠正输入假设"属于哪一层？**

跳出了你的框架。

你的框架：
- **目标层**：约束输出是什么
- **过程层**：约束怎么执行

"纠正输入假设"操作的是**模型推理所依赖的前提**——它既不描述目标形态，也不规定执行步骤，而是修改模型在推理开始前所"相信"的世界状态。

可以叫它**前提层**（或认知前提层）：

```
前提层  →  过程层  →  目标层
（模型相信什么）（怎么做）（做出什么）
```

约束施加得越靠左，需要对抗的模型内部惯性越少。

这也解释了为什么你现有的两处约束（禁令 + 前向影响）都在目标层发力，但模型的错误发生在前提层——两者根本没有对上。

**ClashEval 那个发现的方向需要对齐**

"偏差越大，模型越不倾向于采纳"——这个结论的场景是事实性内容（药品剂量、奥运记录），外部证据与参数记忆在**事实层面**竞争。你的问题是指令与内置行为规范竞争，机制类似但不完全等价。

⚠️ 直接将该结论映射到指令遵循场景是推断，未被直接实验验证。

---

**在指令遵循领域已有直接支持**

Xie et al. 的关键发现：外部证据"连贯且有说服力"才能覆盖参数记忆。这个"连贯"指的是——**不只是给出断言，还给出了使断言合理的上下文**。这与方案 A 的逻辑一致：不是强调禁令，而是让模型看到一个完整的、自洽的世界图景，使其先验推理本身失去触发条件。

---

**你的结论修正版**

> 前提层的问题，**无法被单纯的输出禁令根本解决**；但通过前提修正（让模型在推理之前建立正确的世界假设），可以**有效降低冲突频率，但不能保证消除**。

"根本解决"只有两条路：
1. 微调（改变参数记忆本身）
2. 每次执行时提供足够完整、自洽的前提描述，使模型内置行为规范无法被激活

第 2 条能做到很高的可靠性，但它的上限受模型当次推理质量约束——不是结构性保证。

所以你说"难以被指令层根本解决"——✅ 成立。补充：更精确的表述是"单纯的禁令无法根本解决，前提修正可以大幅改善但仍有残余概率"。这是 LLM 作为推理系统的结构性约束，不是 spec 写法问题。

## AI（Turn 7）

正确，但需要拆分成两个独立的失败模式，而不是一个连续谱。

---

**失败模式一（能力不足型）**：指令未被有效处理

模型没有足够的注意力容量或指令跟随训练，直接跳过了相关约束，完全由参数先验驱动输出。这里没有"冲突被发现但解决错了"，而是冲突根本没有被建立。

**失败模式二（能力足够型）**：冲突被发现，但解决方向错了

这是你这个问题的实际案例——模型读到了禁令，建立了冲突（"spec 说不要占位，但我认为文件不存在不该写链接"），然后用参数先验赢了这场竞争。

---

两者有本质区别：

| | 失败模式一 | 失败模式二 |
|--|--|--|
| 发生位置 | 注意力/解析阶段 | 推理/决策阶段 |
| 冲突是否被建立 | 否 | 是 |
| 提高模型能力是否有帮助 | 有 | 不确定——更强的模型推理也更强，先验更"有理由" |
| 修 spec 是否有帮助 | 有限（连指令都没看） | 有效（冲突已建立，调整前提可改变竞争结果） |

---

**你原话的精确版本**：

> 模型能力低 → 失败模式一概率高，spec 写再好也覆盖不到  
> 模型能力高 → 失败模式二是主要战场，spec 的前提修正策略在这里才真正起作用

补充一个反直觉点：能力越强的模型，在某些场景下失败模式二的"推理质量"反而更高——它能构造出更合理的"为什么不该写链接"的论证，让参数先验赢得更"有道理"。能力提升不是方向一致地改善指令遵从。

你的质疑完全成立——我没有直接证据证明"模型读到了禁令并建立了冲突"。我的判断是基于以下推断链：

1. **spec 中有明确禁令**，且位置靠前、表述清晰。

3. 这种输出方式**与常见 LLM 行为一致**：当模型感知到指令与自身先验冲突时，往往会采取"折中"（如加注释、用占位、加免责声明等），而不是直接无视指令。

所以，这属于**合理推断**，不是事实查证。⚠️

- 让模型自我解释（如"你为什么写了占位？"）
