## 自回归与 Attention 的层次区分

理解 Attention 的第一个障碍，是把它和"预测下一个 token"混为一谈——直觉上容易认为 Attention 在做预测，预测就是 Attention。

这里有一个层次混乱：自回归是 LLM 的**生成策略**（每次只预测一个 token，把预测结果追加进输入，循环往复），而 Attention 是每次预测**内部的计算机制**。两者不在同一层次。

澄清之后，Attention 的定位才能准确：它不是在决定"预测什么"，而是在决定"预测时关注什么"——在生成每个新 token 之前，先在上下文里建立关注关系。

---

## Q、K、V 是什么：从字母到语义

Q、K、V 最初只是三个字母，没有直觉支撑。建立语义理解的有效挂载点是**图书馆检索**：

- **Q（Query）** = 你走进图书馆，手里拿着一张"我想找什么"的纸条
- **K（Key）** = 每本书书脊上的标签，描述"我是关于什么的"
- **V（Value）** = 每本书实际的内容

检索过程：纸条（Q）和每本书的标签（K）比对，得到匹配程度；归一化为权重；按权重抽取每本书的内容（V）混合，得到最终参考资料。

回到 token 语境：当前 token 是"吃"，上下文是"我 喜欢 吃"。"吃"发出 Q（"我在句子里是什么角色？"），每个 token 用 K 回答"我是什么"，被匹配到的 token 用 V 贡献实际语义内容。同一个 token 同时扮演三个角色：作为提问者用 Q，作为被检索对象用 K，被选中后用 V 贡献内容。

**K 和 V 为什么要分成两个？** 直觉上 K 负责"容易被找到"，V 负责"被找到后贡献什么"。这两个目标可能冲突——一个 token 可能需要用简单特征被匹配（K），但贡献复杂语义（V）。强制 K = V 会让两个优化目标互相干扰，分开让模型有自由度分别学习。

## Q、K、V 的来源：权重矩阵与 embedding

Q、K、V 由 token 的 embedding 乘以三个可训练的权重矩阵得到：

```
token embedding × W_Q → Q
token embedding × W_K → K
token embedding × W_V → V
```

容易混淆的点：W_Q、W_K、W_V 是**全层共享**的，不是每个 token 各自一套。所有 token 用同一组权重矩阵变换，但每个 token 的 embedding 不同，算出来的 Q、K、V 也不同。

权重矩阵在推理阶段固定不变；训练阶段持续更新，逐渐学到"K = 容易被匹配、V = 有用内容"的表示。

## Attention 的完整计算流程

有了 Q、K、V，计算分三步：

**第一步：点积——计算匹配分数**

当前 token 的 Q 和上下文每个 token 的 K 做点积，得到一组匹配分数。分数越高，关联越强。

**第二步：softmax 归一化——转换为权重分布**

将匹配分数通过 softmax 转换为加起来等于 1 的权重分布。softmax 使用 $e^x$ 而非直接归一化，原因是 exp 放大大值、压缩小值，让权重分布更集中，梯度也更稳定。

**第三步：加权求和——生成输出向量**

用权重对所有 token 的 V 做加权求和，得到输出向量。输出向量的维度由 V 决定，不由 K 决定。

```
Q · K_i → 匹配分数（对每个 token）
softmax(所有分数) → 权重分布
Σ(权重_i × V_i) → 输出向量
```

Self-Attention 的"Self"指：Q、K、V 全部来自同一个输入序列——每个 token 同时充当提问者、被检索对象和内容提供者。

## 单视角的局限与 Multi-Head Attention

一组 W_Q、W_K、W_V 在一次计算里只能产生一个权重分布——只能从一个视角决定关注谁。

考虑"我喜欢吃苹果"：token"苹果"可能同时需要关注"吃"（食物关系）和"喜欢"（偏好关系）。这是两种不同性质的关系，单头 Attention 无法同时捕捉。

Multi-Head Attention 的解法：同时用多组不同的 W_Q、W_K、W_V 并行计算，每组（每个 Head）学习捕捉不同类型的关系，最后把多个输出向量拼接起来。

拼接后的维度处理：如果直接拼接，8 个 Head 会让维度变成原来的 8 倍。实际做法是每个 Head 的矩阵维度缩小为 `embedding_dim / H`，拼接后恰好还是 `embedding_dim`，再乘以输出权重矩阵 $W^O$ 融合多视角信息：

```
8 个 Head，每个输出 64 维
→ 拼接 → 512 维
→ × W_O → 512 维（维度不变，信息已融合）
```

## Attention 感知不到顺序：Positional Encoding 的必要性

Attention 本身无法感知 token 的顺序。演示这个结论需要一个精确的反例。

最初构造的反例有缺陷——"我喜欢吃"和"吃喜欢我"，这两个输入不仅顺序不同，最后一个 token 也不同，同时改变了两个变量，无法单独验证顺序是否被感知。

正确的控制变量版本：

```
输入A："我 喜欢 吃"
输入B："喜欢 我 吃"
```

两个输入的 token 集合完全相同，最后一个 token 也相同（"吃"），只有顺序不同。由于每个 token 的 K、V 与位置无关，点积结果完全一样，权重分布完全一样，输出完全一样——Attention 感知不到"我"在第 1 位还是第 2 位。

**Positional Encoding 的解法**：在 embedding 上叠加位置向量，让同一个 token 在不同位置的向量表示不同：

```
最终输入 = token embedding + positional encoding
"我"(位置1) = embedding("我") + PE(1)
"我"(位置2) = embedding("我") + PE(2)
```

为什么不直接用整数？整数有两个问题：位置 1000 的值会淹没 embedding 本身的语义信息（embedding 值通常接近 0）；训练时见过位置 1~512，推理时遇到位置 1000 无法泛化。原始 Transformer 使用正弦/余弦函数，值域固定在 [-1, 1]，每个位置有唯一表示，可外推到未见过的位置长度。

位置信息加在 embedding 上还是 Q、K、V 上？原始 Transformer 加在 embedding 上，Q、K、V 全部携带位置信息。后续研究（RoPE，旋转位置编码）只把位置信息加在 Q 和 K 上、不动 V——目前主流 LLM（LLaMA、GPT-4 等）大多采用 RoPE。

## KV Cache：推理加速的工程机制

在自回归生成里，每预测一个新 token，历史 token 的 K、V 都要被重新计算——但这些值没有变化。

这里有一个由主动质疑触发的概念区分：**"缓存的意义"本身有前提条件**。限定在单次请求内（从第一个输入 token 到所有 token 预测结束），历史 K、V 缓存后可直接复用，避免重复计算，这是 KV Cache 的核心价值所在。

```
可以缓存：已生成 token 的 K 和 V（位置信息已包含在内）
不缓存：Q（每次预测只用当前最新 token 的 Q，历史 Q 不再被调用）
不缓存：softmax 权重（依赖当前 Q，每次预测都不同）
```

注意缓存的是**加入位置信息之后**的 K 和 V——同一个 token 在不同位置的 K、V 不同，位置信息必须包含在内。

**跨请求缓存的局限**：加入位置信息后，同一个 token 在不同位置的值不同，跨请求缓存命中率极低。但存在一个由此质疑引出的例外：**Prefix Caching**——多个请求共享完全相同的前缀（如相同的 System Prompt），这段前缀的 K、V 位置相同、内容相同，可以跨请求复用，是生产环境中真实有效的优化。

**KV Cache 的代价**：缓存占用 GPU 显存，序列越长，缓存越大。实践中存在"用显存换计算"的权衡——这是 LLM 推理工程的核心挑战之一。

## 对话中出现的误解（回答者视角）

> 以下是本次对话推导过程中出现的明确偏差，记录在此供后续参考。

| 误解 | 准确表述 |
|------|---------|
| "Q 不能缓存" | 历史 token 的 Q 技术上可以缓存，但缓存了没有意义——每次预测只用当前最新 token 的 Q，历史 Q 不再被调用。问题不是"不能"，而是"无意义"。 |
| 用"我喜欢吃"和"吃喜欢我"演示 Attention 无法感知顺序 | 这个例子同时改变了顺序和最后一个 token，存在两个变量。正确的控制变量版本是"我喜欢吃"和"喜欢我吃"——token 集合和最后一个 token 完全相同，只有顺序不同。 |

## 遗留问题

1. **Positional Encoding 与 KV Cache 的交互细节**：RoPE 将位置信息只作用于 Q 和 K 的点积计算，K 缓存的是"无位置"版本，在某些实现里 KV Cache 更灵活——具体机制尚未展开。
2. **FFN（Feed Forward Network）的作用**：Attention 输出向量之后，Transformer Block 里还有一层 FFN，它在整个流程中承担什么角色尚未覆盖。
3. **W_Q、W_K、W_V 的训练过程**：权重矩阵如何通过训练学到"K = 容易被匹配、V = 有用内容"的表示——梯度下降的具体机制尚未展开。
4. **极端序列长度下 Attention 的失效行为**：$O(n^2)$ 复杂度瓶颈在实际长上下文场景中如何表现，以及现有解法（Sparse Attention、FlashAttention）尚未覆盖。
