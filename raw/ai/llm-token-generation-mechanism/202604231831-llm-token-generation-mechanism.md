## 一、生成的基本单位和节奏

自回归最直观的描述是：用输出 token 预测下一个 token。但"输入端放了什么"值得追问——是只放上一个输出 token，还是放了更多？

答案是放了全部历史：

> 每次预测的输入 = **原始 prompt + 历史所有已生成的 token**

每生成一个新 token，就把它追加进输入，再预测下一个，循环往复。这个节奏决定了自回归天然是串行的——下一步必须等上一步完成。

上下文窗口是这个机制的物理边界。超出后，最早的内容被截断。单次对话一般不触发，多轮对话累积才是主要风险。截断是外部系统（应用层）的工作，不属于自回归机制本身——两者是分开的，不能混淆。

---

## 二、每步预测怎么"看"历史

知道了输入是"全部历史"，下一个问题自然是：模型怎么利用这些历史？全都一视同仁吗？

这里引入 Attention 机制。它做的事可以这样描述：**当前要预测的位置，对历史序列里每个 token 打一个相关性分数**——这个 token 和我当前的预测有多相关？

有一个容易滑入的误解：以为 Attention 是给每个 token 打"重要性"分，好像某个 token 天生就比较重要。实际上分数是**当前预测位置对历史 token 的关系**，不是 token 自身的属性。同一个 token，在预测不同位置时得分可以完全不同。

这也说明了 Attention 是动态的——每预测一个新位置，分数都重新算一遍。比如预测"猫坐在___"的填空时，"猫"和"坐"的得分高；换一个预测位置，整个分布就变了。

附加一个约束：**因果掩码**——当前预测位置只能看它之前的 token，不能看后面的。这保证了生成是单向从左往右的。

---

## 三、Attention 与自回归的分工

Attention 是自回归的底层机制吗？这个问题值得专门说清楚——两者是**分工关系，不是上下级关系**：

- **自回归**：规定了生成的节奏——每次只生成一个 token，把它加回输入，循环
- **Attention**：负责每步预测时怎么看历史——动态计算当前位置对所有历史 token 的关注权重

两者缺一不可：没有自回归，Attention 只是个编码器；没有 Attention，自回归只能机械地看固定窗口，无法动态聚焦。

---

## 四、从"打分"到"一个具体的 Token"

Attention 打完分后，输出的是加权后的上下文表示，经过后续网络处理，最终变成：

> **词表里所有 token 各自的概率**——一个 N 维概率分布

然后从这个分布里选一个 token，就是本步的输出。

这里有个直觉上容易走偏的地方：选概率最高的那个吗？如果每次都选最高概率，同样的输入永远输出同样的结果——LLM 就失去了多样性。实际默认是**按概率分布抽样**：概率高的更容易被选中，但不是必然。这个随机性就是输出多样性的来源。

---

## 五、历史 Token 需要每次重新计算吗

每新增一个 token，Attention 要对整个序列重算一遍吗？

一个直觉上的优化方向：过滤掉低权重的 token，只算权重高的部分——这样不是更高效吗？但这个思路有个漏洞：Attention 是动态的，某个 token 在当前步权重低，不代表后续步也低。

想象用户输入了两个不相关的问题，模型先回答第一个再回答第二个——在回答第二个问题时，attention 的焦点会从第一个问题的上下文转移过来。提前过滤掉"当前步低权重"的 token，后续步需要时就找不回来了。

实际的优化方向不是过滤，而是**缓存**：历史 token 的部分计算结果只依赖它们自身，不会随新 token 加入而改变，可以缓存复用。每步只需要算新 token 自己的部分，历史的直接取缓存。这个优化不改变自回归的任何语义——模型每步仍然"看到"完整历史，没有任何 token 被提前丢弃。

---

## 六、这个设计的本质权衡

把上面的机制串起来：

```
输入：prompt + 历史所有已生成 token
      ↓
Attention：当前预测位置对所有历史 token 动态打分
（因果掩码：只看当前位置之前的 token）
      ↓
后续网络处理 → 全词表概率分布
      ↓
抽样：按概率分布选出下一个 token
      ↓
把新 token 加回输入，重复
```

这个设计用什么换什么？

> **用串行逐步生成（时间成本），换取每步预测时条件完备（能看到全部历史）。**

对比假想的"一次性预测所有 token"：速度快，但每个位置的预测无法参考之前位置的结果，条件严重不足。自回归用时间换来了每步的条件完备性。

最核心的约束只有一个：**每次只预测一个 token**。这个约束决定了自回归天然串行，推理延迟随序列长度线性增长——这是 LLM 推理速度天花板的根源所在。

## 对话中出现的误解（回答者视角）

> 以下是本次对话推导过程中出现的明确偏差，记录在此供后续参考。

| 误解 | 准确表述 |
|------|---------|
| Attention 是给每个 token 自身打重要性分 | Attention 计算的是当前预测位置对每个历史 token 的相关性，是位置间的关系，不是 token 自身的属性 |
| 每次选概率最高的 token | 默认是按概率分布抽样；"选最高"（贪心解码）只是其中一种策略，代价是输出失去多样性 |
| 自回归是"多轮迭代纠正机制" | 自回归是单向串行生成，每步没有回头纠正；依赖的是每步预测时条件完备（能看到全部历史） |
| 优化方式是过滤低权重 token | 实际优化是缓存历史 token 的计算中间结果；Attention 的动态性完全保留，没有 token 被提前过滤 |
