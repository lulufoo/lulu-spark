## 作为程序员，从未感到如此落后
Time: 00:47 - 02:26

Host: 你说你从来没有像现在这样感到作为程序员落后。这从你口中说出来真的让人震惊。这种感觉是令人振奋的，还是令人不安的？

Karpathy: 两者都有。我用 Claude Code 这类 agentic 工具已经有一段时间了。然后 12 月成了一个明确的拐点——我在休假，有更多时间，开始注意到最新的模型生成的代码块就是对的。我不断要求更多，它就是对的。我都记不得上次纠正它是什么时候了。我越来越信任这个系统——然后我就开始 vibe coding 了。这是一次非常剧烈的转变。很多人去年经历 AI 还是把它当成 ChatGPT 这类工具。但你真的需要重新审视 12 月之后发生的事情，因为事情发生了根本性的变化，尤其是这种 agentic 的、连贯的工作流，真正开始跑通了。

## Software 3.0：LLM 作为全新计算范式
Time: 02:28 - 07:36

Host: 你谈到了把 LLM 当作一台新型计算机——不只是更好的软件，而是全新的计算范式。Software 1.0 是显式规则，2.0 是学习权重，3.0 就是现在这个。如果这是真的，一个团队从相信这件事的那天起，会有什么不同的做法？

Karpathy: Software 1.0 ——我在写代码。Software 2.0 ——我在通过创建数据集、训练神经网络来编程。到了 3.0，编程变成了 prompting。Context window 里的内容，就是你操控 LLM 解释器的杠杆，它在数字信息空间里执行计算。一个好例子：Claude Code 发布时，它的安装方式不是 shell 脚本，而是一段你复制粘贴给你的 agent 的文本。你在 3.0 范式里工作——不需要精确列出每个细节，agent 有自己的智能，会读取你的环境、调试循环。

一个更极端的例子：我做了 MenuGen，拍下餐厅菜单的照片，获取菜品的图片。然后我看到了 3.0 版本——直接把照片给 Gemini，说"用 Nanobanana 把菜品叠加到菜单上"。它返回了一张图片，直接在原图的像素里渲染出了各道菜。我整个 MenuGen app 不应该存在。在 3.0 里，神经网络做了大部分的工作，你的 prompt 和图片是输入，输出是图片——中间不需要任何 app 层。

Host: 进一步外推——2026 年版的"90 年代建网站、2010 年代做移动 app"是什么？什么东西在事后回看会显而易见，但今天还几乎没有被构建？

Karpathy: 可以想象完全神经化的计算机——一台设备，将原始视频或音频输入神经网络，用 diffusion 为那个特定时刻渲染一个独特的 UI。50 年代、60 年代，计算机到底会像计算器还是神经网络，其实并不明显。我们走上了计算器这条路。但我觉得这将会翻转——神经网络成为宿主进程，CPU 成为协处理器。神经网络做大部分繁重的工作，工具调用只是一个历史遗留附件，用于确定性任务。外推的终点会是极其陌生的东西——但我们可能会一步一步走到那里。

## 可验证性：自动化的那把尺子
Time: 09:41 - 15:09

Host: AI 在输出可被验证的领域里自动化速度会更快。哪些工作即将以人们没意识到的速度加速？哪些职业人们以为是安全的，但实际上高度可验证？

Karpathy: 传统计算机很容易自动化你能用代码规范化的事情。这一轮 LLM 很容易自动化你能验证的事情——因为前沿实验室把这些模型训练成了巨大的 RL 环境，给予验证奖励。这就是为什么这些模型是参差不齐的——在数学、代码等可验证领域里能力达到峰值，在其他地方则粗糙不堪。

参差不齐的经典例子：像 Opus 4.7 这样的顶尖模型，可以同时重构一个 10 万行代码库或发现零日漏洞，却告诉你走路去 50 米外的洗车场。这说明两件事：要么哪里有点不对，要么你需要留在循环里，把它当工具用。

参差不齐的一部分原因也来自实验室把什么放进了数据分布。从 GPT-3.5 到 GPT-4，象棋能力大幅提升——不是能力的自然进步，而是大量象棋数据进入了预训练集。所以我们某种程度上受制于实验室放进去的东西。如果你在 RL 回路里，你就飞。如果你在数据分布之外，你就挣扎——这时候需要考虑微调。

Host: 对于今天看到了一个可验证领域的 founder，但又担心实验室已经在数学、代码上逃逸速度了——你的建议是什么？

Karpathy: 即使实验室没有聚焦于那个领域，可验证性仍然让你有机会做自己的微调。如果你能在你的领域里创建 RL 环境或示例，就能拉动杠杆，获得真正有效的东西。有些有价值的 RL 环境还没进入实验室的组合——因为对他们来说优先级不高——这就是机会所在。

Host: 什么感觉上可以自动化，但实际上只是远看如此？

Karpathy: 我确实认为几乎所有东西最终都能在某种程度上被验证。即使是写作，你可以想象用一个 LLM 评委委员会，也能得到还算合理的输出。更多的问题是容易还是难。总体来说——一切都是可自动化的。

## Vibe Coding vs. Agentic Engineering
Time: 15:45 - 18:20

Host: 去年你造了"vibe coding"这个词。今天我们进入了更严肃的东西——agentic engineering。两者的区别是什么？你会怎么称呼我们现在所处的阶段？

Karpathy: Vibe coding 是在提升所有人的下限——人人都能 vibe code 任何东西，这很了不起。Agentic engineering 是在维持专业软件原有的质量标准。你不能因为 vibe coding 引入安全漏洞。你仍然对你的软件负责，但你能更快吗？答案是肯定的——但怎么正确地做到？

我叫它 agentic engineering，因为它是一门工程学科。你有这些 agent——能力尖锐但不稳定，有点容易出错，有点随机，但极其强大。如何协调它们在不牺牲质量标准的情况下更快前进？agentic engineering 能力的天花板非常高。以前人们谈论 10x 工程师——我觉得现在被放大了远不止 10 倍。

Host: 如果我们观察两个人用 Claude Code——一个用得很平庸，一个完全 AI 原生——你会怎么描述区别？

Karpathy: 就是充分利用可用工具，投入到自己的环境配置里。就像工程师以前会用好 vim 或 VS Code，现在是 Claude Code 或 Codex。我还认为大多数公司还没有为 agentic engineering 能力重构招聘流程。如果你还在出算法题，那是旧范式。招聘应该是这样的：给一个大项目，让候选人实现它、做好安全性，然后放出一批 agent 尝试攻破它。看他们在那种环境里怎么工作。

## 随着 Agent 做得更多，哪些人类技能会更有价值
Time: 19:29 - 23:30

Host: 随着 agent 做的事情越来越多，哪种人类技能会变得更有价值，而不是更没价值？

Karpathy: 目前 agent 还是实习生级别的存在。你仍然需要负责审美、判断、品味和监督。一个 agent 奇葩行为的好例子：MenuGen 里，用户用 Google 账号注册，但用 Stripe 账号购买积分。我的 agent 试图用 Stripe 邮箱匹配 Google 邮箱来关联资金——但用户两个账号可以用不同邮箱。"为什么要用邮箱地址来交叉关联资金？"这种错误 agent 还会犯。

你必须负责 spec、计划。跟你的 agent 一起设计一份非常详细的 spec——也许让 agent 来写文档——但你负责顶层的监督和类别定义。我已经忘记了 `keepdim` 还是 `keep_dims`、`dim` 还是 `axis`——那是实习生的工作，他们的记忆力很好。但你仍然需要理解 PyTorch 里有 view 和 storage 的区别，不必要地复制内存是低效的。你负责品味、设计、问对问题。agent 来填充细节。

Host: 品味和判断会随着时间推移变得不那么重要吗？还是天花板会不断提升？

Karpathy: 我希望它能改善。目前 RL 里可能没有审美奖励。我看 agent 生成的代码有时会有点心惊——很臃肿，大量复制粘贴，有脆弱的奇怪抽象。能跑，但真的很难看。一个好例子：我的 microGPT 项目——我不断让模型"更简化、再简化"，它就是做不到。你能感受到自己在 RL 回路之外。但这没有根本性的障碍——只是实验室还没做到而已。

## 动物 vs. 幽灵：理解 LLM 的本质
Time: 23:31 - 25:16

Host: 你写了一篇关于动物 vs. 幽灵的文章——我们不是在构建动物，我们是在召唤幽灵。由数据和奖励函数塑造的参差不齐的智能体，没有内在动机、好奇心或进化驱动力。这种框架为什么重要？

Karpathy: 我在尝试弄明白这些东西到底是什么——因为如果你对它们有一个好的模型，你就会更能胜任地使用它们。这些东西不是动物智能。你对它们大喊大叫，不会有任何影响——不会让它们工作得更好或更差。这一切都是统计模拟回路——底层是预训练统计数据，然后 RL 叠加上去，增强了各种能力附件。这是一种心态——什么可能有效、什么可能无效、如何修改系统。我没有五条显而易见的结论。更多的是保持适当的怀疑，随着时间推移摸索。

## Agent 原生的世界
Time: 25:17 - 27:38

Host: 你深度使用了拥有真实权限、本地上下文、代表你采取行动的 agent。当我们所有人都开始生活在那个世界里，它会是什么样的？

Karpathy: 一切都需要重写——一切都还是从根本上为人类而写的。我最大的槽点：我用的各种框架和库，还是有面向人类写的文档。我不想自己做任何事情——我应该复制粘贴什么给我的 agent？每次被告知去某个 URL 或者通过菜单配置 DNS，就很烦。

令人兴奋的问题是：我们如何把需要发生的工作流分解成对世界的传感器和执行器？让一切变得 agent 原生。先描述给 agent。最终我认为我们正走向一个有 agent 代理人的世界——代表人和组织——我的 agent 跟你的 agent 谈来安排会议细节。基础设施需要跟上。

## 在智能变得廉价的时代，什么仍然值得深度学习
Time: 27:39 - 29:42

Host: 随着智能变得廉价，什么仍然值得深度学习？

Karpathy: 最近有一条推文让我印象深刻，我每隔一天都会想起来："你可以外包你的思考，但你无法外包你的理解。"

我仍然是系统的一部分。信息仍然需要进入我的大脑。我感觉自己正在成为一个瓶颈——只是知道我们在构建什么、为什么值得做、如何指挥我的 agent，这些就是瓶颈。必须有什么东西来指挥思考——这仍然从根本上受制于理解。

这也是我对 LLM 知识库感到兴奋的原因——一种处理信息的方式。每次我看到对信息的不同投影，我都会获得洞察。我读一篇文章，我的 wiki 就会被建立起来，我问问题。这些是增强理解的工具。如果没有理解你就无法成为好的指挥者——因为 LLM 肯定不擅长理解。你仍然是理解的唯一负责人。

Host: 非常感谢你来，Andrej，我们真的很感激。
