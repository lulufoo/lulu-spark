# DDM 工作流要改到什么粒度，才不至于「说接了 ACN 其实只动了一半」

> **导航**：[digest](../../../digest/ai-assisted-domain-learning/dialogue-distillation-model/ddm-workflow-optimization-digest.md) | [raw](../../../raw/ai-assisted-domain-learning/dialogue-distillation-model/ddm-workflow-optimization-normalized.md)

> 本文档基于一次**对方案型流程做重构**的对话整理。  
> 目标是重建理解过程：先看清「要的是哪几类契约」，再看到「内嵌/拷贝/删旧」三者在仓库里的真实落点，而不是只记住一句「Phase 5 落盘」。

## 本次对话在追什么

对话从「要把 ACN 接进 DTD、并重新切 Phase4/5 与 digest、三文件用同一 `chat_id`」出发，按一条可重走的主线推进：

- 先把 **数据契约** 说清：raw / distilled / digest 在 CTA 里各是什么、index 在 Phase 4（落盘段）要填什么字段。
- 再决定 ** digest 的读法**：用户选定「要点式」与「3–5 条、按章节从 distilled 抽」，避免再背着「全量事件表」的旧名。
- 然后暴露 **实现偏差**：AI 先按「在主编译里内嵌 ACN 步骤」去改；用户用一句话点破「拷到 `dialogue-distillation-model` 目录」还没做，逼出文件级迁移与删旧 CTA 文件。
- 收束在 **可对照仓库动作** 的一页表：新 ACN 路径、被删的 CTA 路径、谁引用谁。

文末保留：若你本地 `ai-conversation-normalize.md` 与 `dialogue-to-doc.md` 已继续演进，应逐条对比本次 Turn5 的叙述是否仍真。

## 在开口要 digest 之前，三份产物与 index 先要对齐

用户一上来的清单，其实是在定 **四件事绑一条船**：归一化稿放哪、蒸馏稿放哪、digest 放哪、以及 `index.json` 里同一 `chat_id` 上三条路径。对话里用表格把 `raw/…/slug-normalized`、同主题下的 `distilled/…/slug`、同主题下的 `digest/…-digest` 绑在一起，并强调 **子目录要一致**——这不是排版偏好，是后面注入相对导航时少算错一层 `../` 的约束。到这里，[U/AI] 给的是**结构草图**；[U/U] 给的是**约束清单**，两者叠在一起，读者才懂后面为什么要动 ACN 的物理位置，而不只是在文字里加一句「先跑 ACN」。

顺着这条线，**digest 的格式** 必须单独拍板。用户先定了「选项 A」的读感，又在条数上卡到 **3–5**、且 **以 distilled 的章节为源** 做提炼——这等于说：digest 不是对话的再摘要，而是**对成稿学习文档的二次压缩**。[U/AI] 在 Turn2 用对比表把「跟对话走」和「只留 5–8 条」区隔开，[U/U] 把条数与来源收紧，下一节才有明确产出规则。

**路径钩子（若你接着实现）**：对一下当前仓库里 `index.json` 是否已为同一 slug 配齐 `raw`、非空的 `distilled` / `digest` 字段，避免只有 raw 有路径、其余还停在 `null`。

## 真正绷紧的那一下：是「主模型里塞 ACN」还是「目录里放一份 ACN 手册」

Turn1–2 的叙述，很容易读成：只要在 `dialogue-to-doc` 里写「先跑 ACN」，在主编译里插 Phase0，就完成「接 ACN」。**但用户要的是能指着路径说的那种「接」**——直到 Turn3 追问，才发现还没把 **CTA 里的 `ai-conversation-normalize` 以文件身份**迁到 AADL 的 `dialogue-distillation-model/` 下。这里方向翻转是：问题不在「字面上有没有提 ACN」，而在 **可执行物是否在预期目录、旧入口是否仍误导**。[U/U] 的追问把「内嵌大段」打回成「旁挂/迁移文件」；[A/AI] 随后在 Turn4–5 把动作落成「创建新文件、删 CTA 旧文件、把引用从 `{CTA_BASE}/…` 改到 `{AADL_BASE}/…` 下的相对路径」。

如果跳过这一步，只记住「Phase5 会注入导航」，读者仍会在**真实仓库**里迷路——因为**路径与删除**才决定工具链是否一致。

**路径钩子**：打开 `copilot-instructions` 与任何「ACN 快捷链接」，看是否还指向已删除的 CTA 文件。

## 收束时我们在对照什么、而不是在庆祝什么

Turn5 用对照表收束，而不是再铺一层理论，说明对话认可的成功标准是**可核对的工程动作**：`dialogue-distillation-model/ai-conversation-normalize.md` 存在、CTA 侧旧文件被删、主规范里把误插的「整段内嵌」撤回。读者若只想要一句结论，会错过这张表的用途——**它是对照清单**，用来防止下一轮对话又在「同一句需求」上重复造轮子。
