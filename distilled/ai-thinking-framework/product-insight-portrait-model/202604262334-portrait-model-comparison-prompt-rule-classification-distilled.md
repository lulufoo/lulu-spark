## 本次对话在追什么

对话从「比较两个画像模型有什么区别」出发，按一条可重走的主线推进：

- 转折1：比较分析揭示了两者根本是用途不同的工具，而不是版本迭代关系
- 转折2：用户从"新模型更依赖模型能力"中抽象出"填空能力"，引出规则本身的分类问题
- 转折3：用户识别出"灵敏开关"现象——强模型反而更依赖精确措辞，规则并非只减不增

文末保留若干未展开方向，包括"评估型视角如何补入旧模型的成本维度"以及"契约规则精确性的可操作检验方法"。

## 一、两个模型不是进化关系——用途根本不同

对话从一个看似简单的比较请求出发：旧模型（`product-insight-portrait-model`）和新模型（`target-portrait-model`）有什么区别？

读完两个文件，差异的本质浮现得很清楚——**它们解决的是不同问题**，而不是同一问题的两个版本。

旧模型的出发点是"用户面对产品时容易犯三类认知失误：过度乐观、忽略失效场景、选型错位"。它的应对方式是固定7个元素（定位、设计哲学、能力地图、关键机制、设计取舍、成本-价值结构、选型条件），每个元素有明确的提取规则（EG-1~7）和自评清单（L3），用户提供文档，AI 负责提取，一次性生成结构化画像。

新模型的出发点则完全不同——"用户输入主题，但往往不清楚自己想要什么角度"。它的应对方式是先锁定目的（Step 0 门控），再匹配视角原型（5类），再按视角主动搜索信息，最后生成。结构由目的决定，不预设字段，适用范围从产品扩展到人物、历史事件、技术工具、方法论。

这个比较有一个非直觉的推论：**两者不是谁替代谁的关系**。产品选型决策需要成本结构和迁移成本分析，旧模型的固定字段对这类任务覆盖更完整；但旧模型完全无法处理"马斯克是怎么思考的"这类问题，新模型才是正确工具。同一个产品，用途不同，两个模型都可能是正确选择。

顺着这个比较，自然浮现了一个更深的问题：新模型依赖"AI 理解用户意图然后填补结构"——这个能力从哪里来？

## 二、提示词规则混合了两种性质：能力补偿 vs 契约

在这个方向上，你独立识别出一个重要抽象：新模型更灵活的代价，是更依赖模型自身的"填空能力"——整体理解上下文，并精确填补结构空白。随着模型能力提升，原本不得不写的规则自然可以减少。

这个观察是准确的，但规则并不是均质的。提示词里的规则混合了两种性质根本不同的东西：

**能力补偿型规则**：为弥补模型在某个环节做不好而写的约束。旧模型的 [L-A~E] 判别规则（开源产品不要默写"产品团队决策"）、L3 自评清单（生成后逐条检验）、新模型的 Step 0 门控（不确认目的不能继续）——这些规则的存在理由都是"模型容易在这里出错"。

**意图声明型规则（契约型）**：不是补课，而是明确人与模型之间的行为契约。"证据优先"——即使模型能自己推断，显式写出来是为了让行为可审计、可追责。输出格式模板——即使模型能猜到，显式写是为了可预测。

两者随模型演化的走向完全不同：能力补偿型规则随模型增强而收缩；契约型规则不会消失，它的功能是让期望明确，而不是替模型补课。

于是旧模型和新模型在这条轴上的位置就很清楚了：旧模型是高规则密度（大量能力补偿型），在弱模型上稳定；新模型是低规则密度、高能力依赖，在强模型上效果更好，但在弱模型上容易跑偏。**新模型的设计更面向未来——它把"如何做"留给了模型，只规定"做什么"和"底线是什么"**。

但这里还留着一个未解决的张力：如果强模型真的能力更强，它是否也更容易因为"理解"了规则背后的意图，而偏离规则原文？

---

## 三、强模型为什么反而更依赖精确措辞——"灵敏开关"

你观察到一个看起来自相矛盾的现象：模型能力越强，对语言的细微差别越敏感，换一个词可能触发完全不同的执行路径——语言变成了灵敏的开关。这似乎意味着规则反而不能减少，甚至要更精确。

这个张力的解法在于：**问题不是规则多少，而是规则管的是什么任务**。

对于**判断类任务**（深度校准、视角选择、边界识别），正确做法本身就是模糊的，强模型的理解能力越好，越不需要规则介入。此处规则是能力补偿，弱模型需要，强模型不需要。

对于**契约类任务**（输出格式、停止点、标注规则），要求的不是理解，而是精确服从。强模型在这里反而危险——它可能推理出"一个稍微更合理的变体"，然后偷偷偏离原始规则。此处规则是行为约束，不应随模型增强而弱化。

"灵敏开关"现象正是发生在契约类任务上：弱模型对措辞不敏感，大概率按字面执行，差的措辞也能凑合；强模型对措辞极敏感，它会推理出意图，然后按意图执行——而意图和字面可能不一致。

这导致一个反直觉的结论：**强模型上，判断类规则可以减少；契约类规则反而要写得更精确，而不是更少**。提示词设计的成熟方向不是"规则越来越少"，而是把判断类规则还给模型，把契约类规则写得更像规范文档——两者分离，不是混在一起。

## 四、按模型适配提示词会是负担吗——三层结构化的解法

顺着这条推导，你提出了一个实践关切：如果不同模型需要不同的提示词，这对系统长期维护是一个很大的负担。

这个担忧的前提值得检验：**脆弱点实际上集中在一个区域**。

并非所有规则都对模型变化敏感，只有"为某个弱能力专门补偿的判断类规则"是脆弱的——强模型读到"你容易犯X错误，所以必须做Y"，会推断出意图，然后执行一个"更好的Y'"，而不是原始的Y。契约类规则和意图声明类规则对模型变化不敏感：前者强弱模型都能执行，只是强模型需要措辞更精确；后者描述期望而非补偿，强模型反而执行得更好。

而且，按模型调整提示词本来就是已经发生的事——只是叫"迭代"，不叫"适配"。真正的负担不是换模型要改，而是**提示词没有分层，判断类和契约类混在一起，换模型时不知道哪些需要动**。

解法是提示词本身结构化为三层：

```
契约层（稳定，跨模型通用）：格式、停止点、标注规则
意图层（稳定，跨模型通用）：做什么、底线是什么
判断层（随模型能力收缩）：当前模型填空能力不足的补偿规则
```

判断层是唯一需要随模型调整的部分，并且随着模型增强，这一层越来越薄。换模型的成本是递减的，不是线性增长的。**长期走向不是"每个模型一套提示词"，而是提示词越来越短、同时越来越精确**——短是因为判断层收缩，精确是因为契约层的措辞要求更高。

## 遗留问题

1. **评估型视角的缺口补入**：新模型的评估型视角缺少成本-价值结构（许可/计费/隐性成本）和 L3 自评清单。Turn1 已提出"真正的系统化做法是借鉴旧模型"，但未落地为具体改动。
2. **契约规则精确性的可操作检验**：契约类规则"要写得更精确"目前是方向性结论，缺乏"精确到什么程度算够"的操作判据。
3. **判断层收缩速率是否因任务类型而异**：复杂推理场景 vs 格式生成场景，判断层变薄的速率可能不同，这个差异尚未展开。

### 提示词三层结构框架

```
契约层（稳定，跨模型通用）
  └── 格式规范、停止点、标注规则（✅/⚠️/❌）

意图层（稳定，跨模型通用）
  └── 做什么、覆盖范围、底线约束

判断层（随模型能力收缩）
  └── 当前模型填空能力不足的补偿规则
      （换强模型后逐步删除）
```
