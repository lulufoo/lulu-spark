## 本次对话在追什么

对话从一个直觉出发——每个人都带着自身的认知背景和局限与 AI 交互，是否有工具可以打破这个局限——经过多轮推演，最终建立了一个独立的视角扩展工具（暂无正式名称）的完整设计骨架：

- 转折 1：LCCM 只能部分承担这个职责——LCCM 是纵向深化工具，新需求是横向拓宽工具，两者职责异质，强行合并会稀释 LCCM 的核心聚焦
- 转折 2：两个工具的本质区分在于"谁是主体"——LCCM 的对象是"世界（某个概念）"，新工具的对象是"用户自己的认知框架"
- 转折 3：防止退化为 LCCM 的结构性保障——禁止展开概念内容，只输出视角标签；用户的认知描述是必要前置输入
- 转折 4：Phase 5（视角下的内容输出）应直接给出结论，而不是引导式推导——引导式会让工具退化为 LCCM

## 设计的出发点：认知天花板的自我遮蔽

每个人的认知背景决定了他能问出什么问题，而他能问出什么问题决定了他能得到什么答案。这是一个"认知天花板自我遮蔽"的结构性问题——用户不知道自己不知道什么，所以无法提出能突破自身局限的问题。

两个最初设想的维度：
- **客观维度**：提供事物的其他视角
- **主观维度**：不同的人如何对待某事物

LCCM 的视角矩阵（L1-L4 × 10 个侧面）可以作为视角扩展的词汇表，这个判断在对话中通过两个例子得到验证：用户自然产生的视角（WHO/WITH）恰好落在 LCCM 已有的侧面里。

---

## 与 LCCM 的关系：互补而非竞争

LCCM 的视角矩阵确实在做多视角展开，表面上与新工具需求重叠，但本质差异在于认知主体不同：

| | LCCM | 新工具 |
|---|---|---|
| 被审视的对象 | 某个概念/事物 | 用户看待事物的方式 |
| 输入 | 我对这个概念了解多少 | 我是用什么视角在看这个问题 |
| 输出 | 这个概念更深的理解 | 我没有在用但有价值的视角 |
| 问的问题 | "这个事物是什么？"（深度）| "你在用什么镜头看？你还可以换什么镜头？"（元认知）|

**LCCM：给定一个概念，帮你看得更深。**
**新工具：给定你的看法，帮你看到你没看到的角度。**

防退化的结构性保障：禁止展开概念内容（一旦开始展开内容就是退化信号）；工具必须要求用户先描述当前认知（没有这个输入则无法运转）。

两者可以接力：新工具打破视角默认值 → LCCM 深入选定视角。

## 核心流程设计

对话最终确认的完整流程：

```
Phase 1：锚定领域
  AI 提问 → 引导用户说清楚"在谈什么问题/概念"
  输出：领域锚点

Phase 2：充分诊断用户视角（3-5 轮追问）
  AI 通过追问引导用户描述当前认知/做法/理解
  AI 内部识别：用户激活了哪些 LCCM 侧面（视角覆盖地图，内部不输出）

Phase 3：视角匹配
  AI 识别该领域的高价值侧面集合
  差集：高价值侧面 − 用户已覆盖侧面
  输出：3-4 个用户未覆盖、对该领域有价值的视角选项

Phase 4：用户选择视角

Phase 5：直接输出该视角下的客观认知结果
  ├── 该视角下更优的认知/做法是什么（结论式）
  ├── 用户原有视角的具体局限在哪里（对比式）
  └── 如需深化 → 建议交给 LCCM 继续
```

**Phase 2 执行顺序的关键认知**：诊断必须先锚定领域，因为不先知道领域是什么，就无法判断用户的视角是否局限（同一描述在不同领域里的含义完全不同）。

**Phase 5 直接输出而非引导的原因**：工具的核心价值在前四个阶段（诊断、匹配、打破边界），Phase 5 是交付结果，不是学习过程。引导式推导会让工具退化为 LCCM。

## 所有设计决策汇总

| 决策项 | 结论 |
|---|---|
| 独立工具 vs 修改 LCCM | 独立工具 |
| 与 LCCM 的关系 | 共享侧面词汇表；可接力对接 |
| 核心目标 | 打破用户视角局限，识别认知盲区 |
| 防退化约束 | 只输出视角标签，不展开概念内容 |
| 领域锚定时机 | Phase 1 优先，先于视角诊断 |
| 视角诊断方式 | AI 主动提问引导用户描述（不是用户自主陈述）|
| 提问策略 | 充分诊断（3-5 轮追问）|
| 视角输出方式 | 差集法：高价值侧面 − 用户已覆盖侧面 |
| Phase 5 输出方式 | 直接结论式，不引导式推导 |

## 遗留问题

1. 工具名称尚未确定
2. Step 3（该领域高价值侧面集合）的识别方法——静态映射还是动态推断——已选择动态推断，但具体的判断标准尚未在规则中定义
3. 充分诊断（3-5 轮）的具体退出条件——什么时候 AI 判断视角已诊断充分？
4. 与 LCCM 的接力协议——两个工具之间如何传递状态（视角覆盖地图、领域锚点）？
5. 视角输出的数量上限（3-4 个）和选择依据尚未形式化
